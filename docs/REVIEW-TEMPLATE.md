# Review intake — spec sheet, meta, and pipeline

Prepared 2026-07-07. The reviews shelf (`/reviews`) opens only on confirmed
spec sheets. The standing rule from the build log holds: **no fabricated
specs, ever** — a figure that isn't confirmed stays out of the piece. This is
the form that makes that workable.

## 1. The verified spec sheet

One sheet per watch, filled before a word of the review is drafted. Every
line carries its own source. A line without a source stays blank and the
review writes around it — it never approximates.

| Field | Format | Example | Source rule |
|---|---|---|---|
| Brand + model | text | Tudor Pelagos 39 | manufacturer product page |
| Reference | exact, as printed | 25407N | manufacturer page or caseback photo; must satisfy the brand grammar in `lib/verification/references.ts` |
| Case diameter | mm | 39 mm | manufacturer page |
| Case thickness | mm | 11.8 mm | manufacturer page; independent measurement if the maker omits it (say whose) |
| Lug-to-lug | mm (if published) | 47 mm | as above |
| Case material | text | Grade 2 titanium, sandblasted | manufacturer page |
| Movement + calibre | type + number | Automatic, Tudor MT5400 (COSC) | manufacturer page |
| Power reserve | hours (mechanical only) | 70 h | manufacturer page |
| Frequency | vph / Hz (mechanical only) | 28,800 vph (4 Hz) | manufacturer page |
| Water resistance | m | 200 m | manufacturer page |
| Crystal | text | Domed sapphire | manufacturer page |
| Lug width | mm | 21 mm | manufacturer page or strap-fit spec |
| Weight | g + strap config | 105 g on the rubber strap | manufacturer page or a named scale measurement |
| Price | amount + currency + list/street + **date checked** | £3,720 list (GBP), checked 2026-07-07 | manufacturer or authorised dealer page, dated |

**Source per line means**: URL + the date you opened it, and a Wayback
capture where the publisher allows one. Manufacturer product pages move; the
capture is what keeps the sheet honest a year on. If the maker blocks
archiving (Rolex does), note that and lean on an archivable second source
for the load-bearing numbers.

**Price discipline** (matches `data/watches.ts` practice): always hedged,
always dated, rendered as context — never an offer. Currency stated, list
vs street stated.

## 2. The review meta

A review is an MDX piece in `content/essays/` with `mode: "review"` — it
serves at `/reviews/<slug>` and gets the review OG card. The meta export uses
the existing `EssayMeta` shape (`lib/content.ts`). Template:

```ts
export const meta = {
  title: "Tudor Pelagos 39: the titanium diver for people who actually swim",
  dek: "One-sentence standfirst — the argument of the piece, not a summary.",
  silo: "buying-guides",           // reviews live in the buying silo
  pillar: "owning",                // or "instrument" — pick the hub it serves
  mode: "review",                  // this is what routes it to /reviews
  date: "2026-07-10",              // ISO, datePublished
  dateModified: "2026-07-10",      // update on meaningful edits
  readingTime: "8 min",            // COMPUTED — run `npm run reading-time`, never hand-typed
  kicker: "Reviews",
  tags: ["tudor", "dive watches", "titanium"],
  tldr: "A 45–55 word answer-first summary. The reader who stops here should still leave with the verdict and the one number that matters.",
  targetQuery: "tudor pelagos 39 review",   // the head query this page owns
  intent: "commercial",
  relatedSlugs: ["your-first-automatic-what-matters", "water-resistance-for-swimmers"],
  watchesMentioned: ["Tudor Pelagos 39"],   // "Brand Model" — knowledge-graph edges
  emailHook: "Optional per-piece capture hook",
  emailOffer: "Optional offer line",
  faq: [
    { q: "Is the Pelagos 39 good for swimming?", a: "Answer-first, two sentences max." },
    // 3–5 Q&As; rendered as a section and emitted as FAQPage schema
  ],
  sources: [
    { claim: "MT5400 calibre, 70 h reserve, 200 m", url: "https://www.tudorwatch.com/..." },
    // one entry per load-bearing claim — rendered as a foot section and
    // emitted as Article citation URLs. These come straight off the spec sheet.
  ],
  image: {
    src: "/photography/...",
    alt: "Plain description of what is in the frame",
    watch: "Tudor Pelagos 39",
    treatment: "natural",
  },
};
```

Required for a review, beyond the always-required fields: `tldr`,
`targetQuery`, `intent: "commercial"`, `faq`, and `sources` populated from
the sheet. `readingTime` is regenerated by script, never typed.

## 3. The entity entry

Each reviewed watch also gets (or extends) a `WatchEntity` in
`data/watches.ts` — slug `brand/model`, the specs as label/value pairs, the
review's slug in `essaySlugs`, any ledger athletes in `athleteSlugs`, and the
same per-claim sources. This powers the `/watch/[brand]/[model]` page and the
knowledge graph. The file's own discipline applies: a value that isn't on the
sheet is not on the plate.

## 4. Pipeline: sheet → drafted → verified → live

| Stage | Who | What happens |
|---|---|---|
| **Sheet** | Founder (agent may research candidate URLs) | Spec sheet assembled, one source per line, price dated. Nothing drafted before the sheet exists. |
| **Drafted** | Agent | File as `content/essays/_draft-<slug>.mdx` — the `_draft` prefix keeps it out of routes, redirects and the registry. Prose from the sheet and the founder's ride/wear notes; zero figures that aren't on the sheet; voice per `docs/EDITORIAL.md`. |
| **Verified** | Founder | Open every source. Check every line of the sheet against it. Re-check the price and refresh its date. Confirm the verdict is one you'll stand behind under your byline. |
| **Live** | Agent (mechanics), founder (merge) | Rename to `<slug>.mdx`; register it in `content/essays/registry.ts` (import + entry); `npm run reading-time`; add/extend the `WatchEntity`; `npm run build` locally — the prebuild chain (`verify:facts`, `verify:sources`, `voice:check`, `qa:copy`, `voice:corpus`) plus `npm run link:audit` must pass; merge. CI repeats the checks and the e2e suite; the piece serves at `/reviews/<slug>`. |

Division of labour, plainly: **the agent drafts and wires; the founder
confirms the specs and owns the verdict; the build refuses anything
mis-encoded.** Sign-off on a review is the founder's read of the sheet — the
same dual-control idea as the athlete ledger, applied to numbers instead of
wrists.

## 5. Hard rules

1. No spec without a source; no source without a date; archives wherever the
   publisher permits.
2. Price is context, hedged and dated — never an offer, never a link that
   reads like one (affiliate decisions are a separate, explicit call).
3. Athlete claims stay in the ledger: a review never asserts who wears the
   watch on its own authority — it links the athlete page, which renders only
   what has cleared the checks in `lib/verification`.
4. A review the founder hasn't worn, handled, or explicitly framed as
   spec-and-context stays a draft. The byline is the product.
